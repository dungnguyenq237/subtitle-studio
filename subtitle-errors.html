Read subtitle errors and decide what to fix

A subtitle file can look plausible in a text editor and still fail to load. Start with the exact error and a copy of your original file. This guide describes this tool's checks; a warning here is not a universal accessibility or delivery standard.

“Invalid timestamp”

Use two digits for minutes and seconds and three for milliseconds. Minutes and seconds must be between 00 and 59. For example, 00:01:05,250 is valid, while 00:01:65,250 is not. Hours can exceed two digits. This parser also accepts WebVTT-style timestamps without the hours component, such as 01:05.250.

“Must end after it starts”

A cue needs a positive duration. A start at 4 seconds and an end at 3 seconds is invalid, as is a zero-duration cue. Check the intended display interval rather than automatically swapping the timestamps.

“Cannot read subtitle block”

Separate cues with a blank line. Each block must have a timing line, optionally preceded by one identifier line. A missing arrow, stray paragraph or accidentally split caption can prevent parsing.

1
00:00:04,000 --> 00:00:06,500
The kettle is ready.

2
00:00:09,000 --> 00:00:11,000
Pour slowly.

Overlap is a review prompt

The parser warns when a cue starts before the preceding cue ends. Overlap may be intentional for simultaneous speakers, or it may indicate duplicated or poorly timed captions. Read the captions against the video. The tool does not automatically resolve overlaps or sort out-of-order cues.

Long lines and reading time

The tool flags lines over 42 characters. It does not calculate reading speed, understand sentence boundaries or assess the audience's needs. A shorter line can still be unreadable if displayed too briefly. Break text at a natural phrase and check it at the actual playback size.

Encoding and file size

Save your file as UTF-8 in an editor before uploading. The file loader rejects replacement characters that can indicate a decoding problem. It accepts files up to 2 MB. Renaming an unsupported file does not turn it into SRT or VTT.

Keep a useful verification record

Compare the cue count, first and last timestamps and several captions with the original. Keep both versions until the exported file has been checked in the final player. Report reproducible problems using a short non-sensitive example through the Contact page.
