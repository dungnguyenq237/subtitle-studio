Convert SRT and WebVTT with the right expectations

Changing a filename from .srt to .vtt does not convert its contents. Both formats describe timed text, but WebVTT needs a WEBVTT header and uses a dot between seconds and milliseconds. SRT exports from this tool use a comma.

The smallest useful comparison

SRT
1
00:00:06,000 --> 00:00:08,500
The kettle is ready.

WebVTT
WEBVTT

1
00:00:06.000 --> 00:00:08.500
The kettle is ready.

Choose offset 0 when you only want a format conversion. Select WebVTT in “Export as,” process the file, then download it. A nonzero offset changes the timing as well as the format, so check that setting before export.

What this converter keeps

Caption text, line breaks and millisecond cue timing are retained for the supported text-and-timing workflow. Cues are numbered sequentially in output. Inline markup remains text in the exported file; how it appears depends on the target player's support. Preview it in the destination player instead of assuming every markup feature will render identically.

What it deliberately leaves out

WebVTT NOTE, STYLE and REGION blocks are omitted. Positioning settings after a timing line, such as line or position values, are omitted with a warning. Original cue identifiers are replaced by sequential numbers. Consequently, converting to SRT and back is not a lossless backup of a fully styled WebVTT document.

If caption placement identifies speakers, avoids on-screen text or carries other meaning, retain the original and use an editor that preserves those features. This tool is for straightforward caption finishing, not advanced WebVTT layout authoring.

Validate the handoff

  1. Download both examples and compare the header and timestamp punctuation.
  2. Convert the SRT at offset 0 and compare with the expected VTT.
  3. Import the result into your intended player or editor.
  4. Check multiline captions, punctuation and any inline markup in that destination.
